# KHALID DEAL HUNTER

مراقب أسعار Python لأمازون السعودية وجرير مع سجل SQLite ولوحة عربية. أُوقف نون وإكسترا من الاكتشاف والواجهة؛ تبقى البيانات السابقة محفوظة في الأرشيف. الاختبارات المحلية لا تعني أن المتاجر متاحة فعلياً؛ راجع تقرير آخر تشغيل.

## التشغيل

```bash
pip install -r requirements.txt
python -m unittest discover -s tests -v
python main.py
python api.py
```

افتح `http://127.0.0.1:8080`. المسار `/api/dashboard` يعيد JSON للمنتجات والسجل والتقييمات المحفوظة، و`/health` لفحص الاتصال. الواجهة المحلية تستخدم نفس المصدر دون CORS. عند ضبط `API_TOKEN` يتطلب API ترويسة Bearer؛ استخدمه مع عملاء API ولا تضعه في واجهة منشورة. `DASHBOARD_ORIGIN` يسمح بأصل محدد فقط. الخادم المحلي للقراءة والتطوير؛ استعمل خادم HTTPS مناسباً عند نشر Python خارج الجهاز.

اللوحة المستضافة تقرأ `data/dashboard.json` من الفرع main عبر GitHub Raw. هذه واجهة بيانات للقراءة فقط، تحدثها مهمة المراقبة بعد كل فحص. لا تستقبل مفاتيح AI ولا تستدعي خدمات مدفوعة من المتصفح. الأرشيف في مستودع عام، وبالتالي بيانات الأسعار المنشورة عامة كذلك.

## الإعداد

GitHub Secrets: `TG_TOKEN`, `TG_CHAT`, `GEMINI_API_KEY`, `GROQ_API_KEY`. المفاتيح غير متاحة للقراءة من Actions. لم تُضف خدمات مدفوعة؛ استخدام مفاتيح ذات خطة مدفوعة يخضع لحسابك لدى المزود.

متغيرات البيئة: `DB_PATH` (افتراضياً data/deals.db)، `GEMINI_MODEL` (gemini-3.5-flash-lite)، `GROQ_MODEL` (openai/gpt-oss-20b)، `MIN_DROP_PERCENT` (25)، `MIN_HISTORY_POINTS` (7 أيام رصد مستقلة)، `MIN_HISTORY_DAYS` (امتداد 7 أيام)، `MAX_AI_REQUESTS` (8 طلبات لكل تشغيل)، `NOTIFY_NEW_PRODUCTS` (false لتجنب إغراق القناة).

## التحقق التاريخي

تُحفظ جميع الأسعار الصالحة. القراءات المتطابقة خلال ساعة لا تتكرر؛ تغير السعر يُحفظ فوراً. يُحسب وسيط كل يوم ثم يستبعد الشذوذ بأكبر هامش بين 20٪ وثلاثة أضعاف الانحراف المطلق الوسيط. خط الأساس هو الأصغر بين الوسيط المنقح ووسيط الأيام السبعة الأخيرة. يلزم عدد أيام كافٍ وامتداد كافٍ وآخر رصد خلال أسبوع. تُستخدم نافذة 90 يوماً. لا تدخل القراءة الحالية في خط أساس نفسها.

الحالات: NEW_PRODUCT، INSUFFICIENT_HISTORY، POTENTIAL_DEAL، VERIFIED_DEAL، PRICE_NORMAL، PRICE_INCREASED، DATA_ANOMALY. السعر الأصلي الذي يدعيه المتجر إشارة محتملة فقط ولا يثبت الخصم. الانخفاضات شديدة الشذوذ لا توثق آلياً.

## الذكاء الاصطناعي والإشعارات

Gemini أولاً ثم Groq. الرد JSON ويخضع لفحص اللغة ورفض الأرقام والروابط وادعاءات التحقق في التعليق. التطبيق يضيف الأرقام والحالة والرابط من البيانات. يحفظ التقييم منفصلاً عن الحقائق، ويعاد استخدامه سبعة أيام ما لم تتغير المعلومات المهمة. حد الطلبات وقاطع أعطال مؤقت يحميان زمن الفحص والحصة؛ عند غياب التقييم يستخدم قالب عربي صريح. لا نعطي درجة جودة عددية بلا أدلة.

تُرسل العروض الموثقة حتى إن لم يوصِ AI بالمنتج. يُحفظ سجل التنبيهات بعد قبول Telegram فقط. لا يكرر السعر والحالة نفسيهما، ويسمح بتغير الحالة أو تغير السعر بخمسة بالمئة. لا يوجد ضمان إرسال مرة واحدة عند انقطاع الاتصال بعد قبول Telegram وقبل تسجيل النتيجة محلياً.

## الاكتشاف والموثوقية

تدوير الاستعلامات محفوظ في قاعدة البيانات، وتُستخدم فئات متنوعة مناسبة لكل متجر. الافتراضي أربعة استعلامات لكل متجر، وحتى ثلاث صفحات و40 منتجاً لكل بحث، بسقف 160 منتجاً لكل متجر. تُعطى أولوية للعروض المعلنة 25٪ فأكثر، ويُعاد فحص 12 منتجاً مؤرشفاً لكل متجر لبناء السجل. تتحكم المتغيرات QUERIES_PER_STORE وMAX_SEARCH_PAGES وMAX_PRODUCTS_PER_SEARCH وMAX_PRODUCTS_PER_STORE وTRACKED_PRODUCTS_PER_STORE في هذه الحدود. يدعم المحلل JSON-LD وJSON المضمن والبطاقات والبيانات الوصفية وروابط المنتجات، ويرفض الروابط الخارجية والأسعار المتعارضة. لا نتجاوز CAPTCHA أو التحكم في الوصول؛ قد تحتاج المتاجر إلى مصدر عام رسمي يتيحه مالك المتجر إذا استمر الحجب.

جدولة Actions كل 15 دقيقة كما كانت، وقد يؤخرها GitHub. الفحص الجزئي أو المتاجر الفارغة ينتج فشلاً ظاهراً بعد حفظ البيانات. يتم checkpoint لـ WAL وتصدير JSON وحفظ نسخة استرداد ضمن artifacts قبل محاولة دفع الأرشيف، ولا يستخدم force push. إذا تغير main بالتزامن وفشل الدفع، تبقى النسخة في artifact لاستردادها؛ لا نستبدل قاعدة أحدث بقاعدة أقدم.

## الاختبار الحي

```bash
python integration_scan.py
```

ينفذ بحثين متنوعين لكل من أمازون السعودية وجرير ويؤرشف النتائج الصحيحة دون إرسال Telegram أو طلب AI. ينتج integration-results.json. يمكن تغيير العدد عبر INTEGRATION_QUERIES_PER_STORE. استخدم DB_PATH لنسخة منفصلة إن رغبت. لا تُحذف البيانات القديمة ولا تُخترع منتجات لتعويض الحجب.


## التوفير والثقة في الواجهة

تفصل الواجهة بين سعر المتجر الأصلي المعلن وخط الأساس التاريخي. يُحسب الفرق بالريال والنسبة باستخدام Decimal وتقريب منزلتين. المرجع غير الموجود يعرض «غير متاح»، ولا يُستبدل بسعر مختلق. الخصم المعلن لا يثبت التوفير. اختلاف الادعاء عن الانخفاض التاريخي بعشر نقاط مئوية أو أكثر يُوصف بأنه مبالغ فيه مقارنة بالسجل، ولا يُعد اتهاماً بالاحتيال.

حد 25٪ مخصص لاكتشاف العروض المعلنة وإبرازها. بعد اكتمال شروط السجل يصبح أي انخفاض موجب حقيقي عن خط الأساس عرضاً موثوقاً، وتظهر نسبة الانخفاض التاريخي الفعلية حتى لو كانت أقل من 25٪. لا تُستخدم نسبة المتجر بديلاً عنها. الصور من مصدر المنتج الفعلي؛ غيابها يعرض رسالة واضحة دون صورة مخمّنة.

درجة الثقة دليل قوة بيانات من 100، وليست احتمالاً أو تقييماً للجودة: الهوية 10، الحداثة 20، التاريخ الكافي 50، المقارنة المطابقة المؤكدة الحالة 20. نقص التاريخ أو سعر أقدم من يوم يقيدان الدرجة عند 39؛ الشذوذ يعطي صفراً. كل المكونات والأسباب معروضة. حتى الدرجة المرتفعة لا تعني تلقائياً أن المنتج يستحق الشراء.

المقارنة بين المتاجر تشترط GTIN صالحاً ومطابقاً، وترفض اختلافات الطراز والسعة واللون والحالة المعروفة. حالة غير معروفة تُعرض كمقارنة أولية ولا تكسب نقاط مقارنة. الشحن والرسوم غير المتاحة لا تُفترض صفراً. لا توجد مطابقة تلقائية بالأسماء المتشابهة.

تجدد الواجهة الأرشيف كل دقيقة أثناء ظهور الصفحة، مع منع الطلبات المتداخلة وتنبيه انقطاع الاتصال والبيانات القديمة، وتحافظ على الفلاتر والمفضلة المحفوظة محلياً. لا يعني تحديث الصفحة أن المتاجر نجحت في توفير قراءة جديدة. تُعرض البطاقات على دفعات لتحسين الأداء، وتُجلب قراءات الأرشيف بعملية مجمعة بدلاً من استعلام لكل منتج.

## توثيق المصدر وترحيل الإصدار 5

تبقى كل القراءات السابقة محفوظة. بسبب اكتشاف أخطاء فعلية في المحلل القديم (عناوين أسعار وروابط بحث بدلاً من المنتجات)، توسم القراءات القديمة التي لم تخضع لمسار التحقق الجديد بأنها أرشيف غير مدقق. لا تستخدم لإثبات خصم حتى تتوفر قراءات جديدة موثقة. تُعرض في السجل وتُحسب ضمن إجمالي الأرشيف؛ لا تُحذف. حقل validated يميز القراءات الجديدة، ويظل المرجع غير كافٍ عند غيابها. تم إصلاح روابط Amazon لتوحيد ASIN وإزالة تتبع البحث ومنع أرشفة صفحة البحث كمنتج.

جرير: يُقرأ مفتاح فهرس البحث العام من حالة Nuxt التي تنشرها الواجهة، ويُستخدم طلب البحث المجهول نفسه الذي يستخدمه المتجر. ثم تُجلب الأسعار النهائية من واجهة الكتالوج العامة للمتجر بحسب SKU. لا نستخدم بيانات عميل أو مفاتيح خاصة ولا نعتبر سعر فهرس البحث بديلاً عن سعر الكتالوج. المنتجات متعددة المتغيرات غير المحددة تُستبعد.
