# KHALID DEAL HUNTER

بوت Python لمراقبة أسعار المنتجات في Amazon.sa وNoon وExtra وJarir، مع تنبيهات Telegram وتحليل اختياري عبر Gemini ثم Groq.

## التشغيل
- GitHub Actions يحاول تشغيل الفحص كل 15 دقيقة، ويمكن تشغيله يدوياً من تبويب Actions.
- عند بدء التشغيل، يرسل البوت رسالة تأكيد إلى Telegram.
- بعد ذلك يفحص المتاجر. لا يرسل تنبيه عرض إلا إذا وجد منتجاً اجتاز شروط سجل الأسعار وتحليل الذكاء الاصطناعي.
- GitHub Actions ليس خادماً دائماً؛ قد تتأخر الجدولة، ولا يضمن هذا الفاصل الزمني تشغيل المهمة بالضبط كل 15 دقيقة.

## المتاجر وطرق الاستخراج
يحاول المحلل عدة مصادر للبيانات حسب ما تعرضه صفحة المتجر:
1. بيانات Product المنظمة (JSON-LD).
2. بيانات JSON المضمنة وحالة تطبيقات الويب (embedded state).
3. بطاقات المنتجات وعناصر HTML ومحددات خاصة بكل متجر.
4. روابط المنتجات مع فحص العناصر الحاوية بحثاً عن السعر.
5. وسوم Meta كخيار احتياطي.

تُجرّب مسارات بحث بديلة ورؤوس متصفح مكتبي/جوال مع إعادة المحاولة للأخطاء المؤقتة. قد تظل بعض الصفحات غير قابلة للقراءة إذا اعتمدت على JavaScript أو حجبت الطلبات الآلية أو غيّرت تصميمها. لا يحاول المشروع تجاوز CAPTCHA أو أنظمة الحماية.

## سجل الأسعار
- يُحفظ سجل الأسعار في `data/deals.db` ويُعاد حفظه في GitHub بعد التشغيل.
- يحتاج المنتج إلى 3 قراءات سابقة على الأقل قبل تقييم الانخفاض.
- يقارن السعر الحالي بوسيط آخر 12 قراءة، ويشترط انخفاضاً لا يقل عن 25%.
- هذه الشروط تقلل التنبيهات غير الموثوقة، لكنها قد تؤخر أول تنبيه لمنتج جديد.

## الذكاء الاصطناعي
- Gemini هو المزود الأساسي.
- Groq هو البديل عند غياب Gemini أو فشله.
- إذا فشل الاثنان، لا يرسل البوت توصية مولدة غير موثوقة.

## أسرار GitHub المطلوبة
أضف القيم من Settings > Secrets and variables > Actions:
- `TG_TOKEN`
- `TG_CHAT`
- `GEMINI_API_KEY`
- `GROQ_API_KEY`

لا تضع المفاتيح داخل ملفات المشروع أو ترسلها في المحادثات.

## الاختبارات
يُشغّل الـ workflow فحص صياغة Python واختبارات انحدار للمحلل قبل بدء فحص المتاجر.
