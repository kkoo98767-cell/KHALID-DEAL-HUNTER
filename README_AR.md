# KHALID DEAL HUNTER

مراقب أسعار Python للمتاجر الأربعة مع سجل SQLite ولوحة عربية. يحتفظ المشروع بالأرشيف حتى عند تعطل المتاجر أو مزودي الذكاء الاصطناعي. الاختبارات المحلية لا تعني أن المتاجر متاحة فعلياً؛ راجع تقرير آخر تشغيل.

## التشغيل

```bash
pip install -r requirements.txt
python -m unittest discover -s tests -v
python main.py
python api.py
```

افتح `http://127.0.0.1:8080`. المسار `/api/dashboard` يعيد JSON للمنتجات والسجل والتقييمات المحفوظة، و`/health` لفحص الاتصال. الواجهة المحلية تستخدم نفس المصدر دون CORS. عند ضبط `API_TOKEN` يتطلب API ترويسة Bearer؛ استخدمه مع عملاء API ولا تضعه في واجهة منشورة. `DASHBOARD_ORIGIN` يسمح بأصل محدد فقط. الخادم المحلي للقراءة والتطوير؛ استعمل خادم HTTPS مناسباً عند نشر Python خارج الجهاز.

اللوحة المستضافة تقرأ `data/dashboard.json` من الفرع main عبر GitHub Raw. هذه واجهة بيانات للقراءة فقط، تحدثها مهمة المراقبة بعد كل فحص. لا تستقبل مفاتيح AI ولا تستدعي خدمات مدفوعة من المتصفح. الأرشيف في مستودع عام، وبالتالي بيانات الأسعار المنشورة عامة كذلك.

## الإعداد

GitHub Secrets: `TG_TOKEN`, `TG_CHAT`, `GEMINI_API_KEY`, `GROQ_API_KEY`. المفاتيح غير متاحة للقراءة من Actions. لم تُضف خدمات مدفوعة؛ استخدام مفاتيح ذات خطة مدفوعة يخضع لحسابك لدى المزود.

متغيرات البيئة: `DB_PATH` (افتراضياً data/deals.db)، `GEMINI_MODEL` (gemini-2.5-flash)، `GROQ_MODEL` (openai/gpt-oss-20b)، `MIN_DROP_PERCENT` (25)، `MIN_HISTORY_POINTS` (7 أيام رصد مستقلة)، `MIN_HISTORY_DAYS` (امتداد 7 أيام)، `MAX_AI_REQUESTS` (8 طلبات لكل تشغيل)، `NOTIFY_NEW_PRODUCTS` (false لتجنب إغراق القناة).

## التحقق التاريخي

تُحفظ جميع الأسعار الصالحة. القراءات المتطابقة خلال ساعة لا تتكرر؛ تغير السعر يُحفظ فوراً. يُحسب وسيط كل يوم ثم يستبعد الشذوذ بأكبر هامش بين 20٪ وثلاثة أضعاف الانحراف المطلق الوسيط. خط الأساس هو الأصغر بين الوسيط المنقح ووسيط الأيام السبعة الأخيرة. يلزم عدد أيام كافٍ وامتداد كافٍ وآخر رصد خلال أسبوع. تُستخدم نافذة 90 يوماً. لا تدخل القراءة الحالية في خط أساس نفسها.

الحالات: NEW_PRODUCT، INSUFFICIENT_HISTORY، POTENTIAL_DEAL، VERIFIED_DEAL، PRICE_NORMAL، PRICE_INCREASED، DATA_ANOMALY. السعر الأصلي الذي يدعيه المتجر إشارة محتملة فقط ولا يثبت الخصم. الانخفاضات شديدة الشذوذ لا توثق آلياً.

## الذكاء الاصطناعي والإشعارات

Gemini أولاً ثم Groq. الرد JSON ويخضع لفحص اللغة ورفض الأرقام والروابط وادعاءات التحقق في التعليق. التطبيق يضيف الأرقام والحالة والرابط من البيانات. يحفظ التقييم منفصلاً عن الحقائق، ويعاد استخدامه سبعة أيام ما لم تتغير المعلومات المهمة. حد الطلبات وقاطع أعطال مؤقت يحميان زمن الفحص والحصة؛ عند غياب التقييم يستخدم قالب عربي صريح. لا نعطي درجة جودة عددية بلا أدلة.

تُرسل العروض الموثقة حتى إن لم يوصِ AI بالمنتج. يُحفظ سجل التنبيهات بعد قبول Telegram فقط. لا يكرر السعر والحالة نفسيهما، ويسمح بتغير الحالة أو تغير السعر بخمسة بالمئة. لا يوجد ضمان إرسال مرة واحدة عند انقطاع الاتصال بعد قبول Telegram وقبل تسجيل النتيجة محلياً.

## الاكتشاف والموثوقية

تدوير الاستعلامات محفوظ في قاعدة البيانات، وتُستخدم فئات مناسبة لجرير وإكسترا. يُعاد فحص ثلاثة منتجات قديمة بعد بحث ناجح لبناء السجل. الصفحات المحددة بروابط التالي تُفحص ضمن ميزانية محدودة. يدعم المحلل JSON-LD وJSON المضمن والبطاقات والبيانات الوصفية وروابط المنتجات، ويرفض الروابط الخارجية والأسعار المتعارضة. لا نتجاوز CAPTCHA أو التحكم في الوصول؛ قد تحتاج المتاجر إلى مصدر عام رسمي يتيحه مالك المتجر إذا استمر الحجب.

جدولة Actions كل 15 دقيقة كما كانت، وقد يؤخرها GitHub. الفحص الجزئي أو المتاجر الفارغة ينتج فشلاً ظاهراً بعد حفظ البيانات. يتم checkpoint لـ WAL وتصدير JSON وحفظ نسخة استرداد ضمن artifacts قبل محاولة دفع الأرشيف، ولا يستخدم force push. إذا تغير main بالتزامن وفشل الدفع، تبقى النسخة في artifact لاستردادها؛ لا نستبدل قاعدة أحدث بقاعدة أقدم.

## الاختبار الحي

```bash
python integration_scan.py
```

ينفذ بحثاً عاماً في المتاجر الأربعة ويؤرشف النتائج الصحيحة دون إرسال Telegram أو طلب AI. ينتج integration-results.json. استخدم DB_PATH لنسخة منفصلة إن رغبت. لا تُحذف البيانات القديمة ولا تُخترع منتجات لتعويض الحجب.
